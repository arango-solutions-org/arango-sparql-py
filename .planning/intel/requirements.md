# Requirements (PRD intel)

Extracted from `docs/architecture/PRD.md` — "Product Requirements Document —
`arango-sparql-py` v1" (Draft v1, owner Arthur Keen). The PRD declares §3
"Success criteria (v1.0 acceptance)" as **the contract**; each criterion is
independently measurable by a named test/artefact. All requirements below share:

- source: /Users/plosiewicz/dev/arango-sparql-py/docs/architecture/PRD.md

Mission (context for the requirements): replace the legacy JS Foxx
`arango-sparql` with a standalone Python microservice that transpiles SPARQL 1.1
→ ArangoDB AQL with W3C-grounded correctness, exposes a W3C SPARQL 1.1 Protocol
endpoint, adapts to PG/LPG/RPT/hybrid physical schemas, supports NL→SPARQL, and
mirrors `arango-cypher-py`.

## Non-goals (v1) — explicit scope exclusions

- SPARQL 1.1 Update (`INSERT DATA`/`DELETE DATA`/`LOAD`/`CLEAR`/`CREATE`/`DROP`/`COPY`/`MOVE`/`ADD`) — writes go through AQL directly.
- Federated query (`SERVICE`) — out of scope for v1; Service Description advertises no `sd:BasicFederatedQuery`. Possible v2.
- Inferencing/reasoning (RDFS/OWL entailment) — ontology is mapping metadata, not a reasoning surface.
- Multi-tenancy across separate processes — sessions are per-process in-memory; needs sticky-session LB.
- Replacing AQL — this is a transpiler, not a competing engine.

## REQ-w3c-coverage (§3.1)
W3C DAWG translation coverage ≥ 25%, with no single XFAIL bucket consuming > 30%
of remaining failures.
- acceptance: `tests/w3c/COVERAGE_REPORT.md`; tracked (not gated) by `tests/w3c/test_w3c_query_evaluation.py` via imperative `pytest.xfail`; regenerated by `analyze_coverage.py --write`.
- status note: current measured 96.4% (bar cleared by 71pp). The 30% sub-clause is consciously accepted as violated (dominant bucket = SPARQL federation/SERVICE, a single intentionally-deferred feature). See INGEST-CONFLICTS INFO.

## REQ-sparql-protocol-endpoint (§3.2)
Conformant W3C SPARQL 1.1 Protocol endpoint. `GET/POST /sparql` honours `Accept`
for JSON/XML/CSV/TSV (RFC 9110 §12.5.1 q-value parsing); `GET /sparql` with no
query returns Service Description as `text/turtle`; documented error contract in
force (405 on Update forms, 400/422/406/503/504/429/401 per §5.2 table).
- acceptance: `tests/test_sparql_protocol_*.py` (accept negotiation, errors, service description).

## REQ-physical-model-coverage (§3.3)
Translator emits correct AQL against every physical shape in §6.1 — PG
(`COLLECTION`), LPG (`LABEL`), RPT (`_triples`), plain `DOCUMENT` — plus PG+LPG
and PG+RPT hybrids and both edge styles (`DEDICATED_COLLECTION`,
`GENERIC_WITH_TYPE`).
- acceptance: `tests/translate/{bgp_select,hybrid,rpt}.yml`, `tests/cross/test_multimodel_cross.py`, `tests/cross/test_edge_traversal_cross.py`, `tests/schema/test_fixtures.py`.

## REQ-hybrid-bgp-translation (§3.4)
One SPARQL BGP whose triples touch ≥ 2 physical models translates to a single
AQL query (not rejected, not split), joined on shared subject URI.
- acceptance: `tests/translate/hybrid.yml`, `tests/cross/test_hybrid_cross.py`.
- additional mixed-model binding parity: `tests/cross/test_multimodel_cross.py`.

## REQ-schema-detection (§3.5)
Both schema detectors ship (algorithmic heuristic + analyzer-backed); analyzer
wins on `strategy="auto"`; classifies the sister project's mapping-fixture
corpus + this project's RPT fixtures with zero false negatives.
- acceptance: `tests/schema/test_classify.py`, `tests/schema/test_acquire.py`, `tests/schema/fixtures/*.export.json`.

## REQ-schema-http-parity (§3.6)
All 9 schema/mapping HTTP routes exist with documented response shapes, matching
`arango-cypher-py`.
- acceptance: `tests/test_service_schema_routes.py`; routes listed in §5.1/§6.4.

## REQ-foxx-parity (§3.7)
Static semantic parity with archived Foxx `arango-sparql` fixtures: every
translatable inventoried fixture has a Python semantic-parity case or golden
emitting semantically equivalent AQL (≥ 90% of the inventory passes).
- acceptance: `tests/legacy/test_legacy_semantic_parity.py`.
- status note: initial three-query inventory exists; the ≥90% inventory target
  remains pending until the archived Jest query corpus is fully enumerated.

## REQ-operational-parity (§3.8)
Measurable operational parity with `arango-cypher-py`: identical session /
connect / public-mode / CORS / rate-limit / SSRF / redaction / startup-guard
surface; one CI test per surface.
- acceptance: `tests/parity/test_cypher_py_*.py` (one file per §8 row).

## REQ-ui-parity (§3.9)
UI feature parity with `arango-cypher-py`'s workbench: every §10.2 + §10.3
capability-table row has a passing Playwright test.
- acceptance: `ui/tests/playwright/parity.spec.ts` (CI-blocking).

## REQ-thirdparty-tool-compat (§3.10)
Every "verified-compatible" tool row of §11.1 has a passing smoke test (≥ 1
SELECT, 1 ASK, and the Service Description fetch). Tools: Protégé, YASGUI,
SPARQLWrapper, Microsoft Ontology Playground, etc.
- acceptance: `tests/integration/test_*_compat.py` (one per tool).

## REQ-ontoextract-integration (§3.11)
`arango-ontoextract` can (a) point its PRD Q7 endpoint at us, (b) seed a library
entry via `/mapping/export-owl`, (c) accept a curated OWL push via
`/mapping/import-owl`.
- acceptance: `tests/integration/test_aoe_roundtrip.py` (Docker-gated, both services live).

## REQ-performance-slos (§3.12)
Every §9.4 performance budget row passes its benchmark within ≤ 25% of the
stated p95.
- acceptance: `tests/perf/test_*.py` (CI-blocking on > 25% regression).

## REQ-threat-model-mitigations (§3.13)
Every row of the §8.6 STRIDE threat matrix has its asserting test.
- acceptance: `tests/security/test_*.py` (CI-blocking).

## REQ-privacy-contract (§3.14)
No-bodies-in-logs property test passes; `ARANGO_SPARQL_LOG_JSON=1` emits the §9.5
envelope; opt-in tenant-label toggles behave per §17.2.
- acceptance: `tests/security/test_no_body_in_logs.py`, `tests/test_log_envelope.py`.

## REQ-config-appendix-normative (§3.15)
Adding a new env var without updating Appendix A fails CI.
- acceptance: `tests/test_config_appendix.py` (introspects `arango_sparql/_env.py` vs the appendix table).

## REQ-public-release-readiness (§3.16)
Repo public; CI green on Python 3.11/3.12/3.13 + ArangoDB 3.11/3.12; MIT LICENSE
+ CONTRIBUTING + SECURITY + operational runbook published; repeatable
`docker compose up` dev loop; SBOM artefact attached to the v1.0 release tag.
- acceptance: GitHub releases page; CI history; `docker compose up && curl /health/ready`.
